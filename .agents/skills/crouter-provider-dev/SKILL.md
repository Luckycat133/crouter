# Universal crouter Provider Development

Use the stages below to locate the affected provider contract. A new provider may need all stages; a scoped correction should change and verify only its affected surfaces. For an existing runtime failure without a provider redesign, use `crouter-runtime-diagnostics`.

---

## Architecture & Core Invariants

All providers added to `crouter` must adhere to these non-negotiable architectural invariants:

1. **Protocol Acceptance Gate**:
   - `crouter` strictly targets the Anthropic Messages protocol (`POST /v1/messages`).
   - Every provider URL must be the base prefix **before** `/v1/messages`. Never append `/v1/messages` to `BASE_URL`, `PLAN_URL`, or `API_URL`.
   - Gateways speaking only OpenAI format (direct OpenAI, Baichuan) cannot be added directly; they require a dedicated translation proxy (e.g. `codex` via `codex-proxy`).

2. **Billing Surface & Quota Guardrails**:
   - Subscription plans (Coding Plan, Agent Plan, Token Plan) and pay-as-you-go APIs are independent surfaces (`AUTH_MODE="surfaces"`).
   - Plan routes must consume monthly prepaid/token quotas and must never silently trigger unconfirmed cash billing.

3. **Zero-Collision Session-Scoped MCP Switching**:
   - All MCP servers are dynamically generated by `lib/provider-assets.js` into an isolated temporary file (`mktemp -t crouter-mcp.XXXXXX`) with mode `0600`.
   - Injected into Claude Code via `--mcp-config <tmpfile>` and `--strict-mcp-config`.
   - Cleaned up immediately upon session exit (`trap cleanup_provider_assets EXIT INT TERM`).
   - **`~/.claude.json` is NEVER modified.** Switching between providers completely swaps tool sets with zero pollution or leftover state.
   - Pure model gateways without companion tools use `ASSET_PROFILE="empty"` to ensure zero overhead.

4. **POSIX Portability**:
   - All shell files must run cleanly under POSIX `/bin/sh` across macOS, Linux (`dash`), and BSD.
   - No bashisms (`[[ ]]`, `function`, `local`, arrays).

## Provider Development Stages

For a new integration, consider these stages in dependency order. For an existing integration, start at the affected stage; do not reconfigure MCP, reinstall launchers or alter gateway routing when those contracts are unchanged:

```
[Phase 1: 查官方文档] ➔ [Phase 2: 写参数] ➔ [Phase 3: 配置自动化切换 MCP] ➔ [Phase 4: 统一网关集成] ➔ [Phase 5: 严密验证与闭环]
```

---

### Phase 1: 查官方文档 (Primary Source Verification & Audit Gate)

Never guess parameters, model IDs, context lengths, or authentication headers. Consult vendor primary sources first:

1. **Verify Anthropic Compatibility**:
   - Confirm official documentation lists an Anthropic Messages-compatible base URL.
   - Extract the base URL prefix (strip `/v1/messages`).
2. **Identify Billing Surfaces**:
   - Check if vendor offers separate subscription plans (Coding Plan, Token Plan) vs pay-as-you-go APIs.
   - If dual surfaces exist, determine separate endpoints, key env names, and model mappings.
3. **Record Exact Model IDs & Casing**:
   - Copy exact casing and punctuation (e.g. `MiniMax-M3`, `glm-4-plus`, `deepseek-v4-flash:q8`).
   - Map models to tiers: default `MODEL`, `MODEL_OPUS`, `MODEL_SONNET`, `MODEL_HAIKU`, `MODEL_SUBAGENT`.
4. **Distinguish Context Window & Auto-Compaction**:
   - Document maximum context limit (`CONTEXT_TOKENS`).
   - Document vendor-recommended auto-compaction window (`AUTO_COMPACT_TOKENS`). Never conflate them.
5. **Inspect Companion Tools**:
   - Check if vendor publishes official MCP servers (PyPI, npm, streamable HTTP, SSE).
6. **Record in `docs/provider-audit.md`**:
   - Add primary source URLs, check date, and design decisions.

> See [Audit & Acceptance Reference](references/audit-and-acceptance.md) for full acceptance checklists and documentation guidelines.

---

### Phase 2: 写参数 (Provider Contract in `providers/<provider>.sh`)

Select the archetype that matches the vendor's integration model and create `providers/<provider>.sh`:

1. **Select Archetype**:
   - **Type 1: Dual-Surface Subscription Plan (`AUTH_MODE="surfaces"`)**: MiniMax, DashScope, Qianfan, Tencent, StepFun, Z.AI.
   - **Type 2: Single-Surface API Key / Pure Gateway (`AUTH_MODE="env"`)**: DeepSeek, Moonshot, Xiaomi, Huawei.
   - **Type 3: Third-Party Aggregator (`AUTH_MODE="env"`)**: OpenRouter, SiliconFlow, 302.ai, AIHubMix, Infini, PPIO.
   - **Type 4: Local Translation Proxy (`AUTH_MODE="none"`)**: Codex (port 19000), Ollama (port 11435), Antigravity.
   - **Type 5: Native Cloud Backend (`AUTH_MODE="native"`)**: Bedrock, Vertex AI.

2. **Populate Parameters**:
   - Identity: `PROVIDER_NAME`, `PROVIDER_DESC`
   - Endpoints: `BASE_URL` (or `PLAN_URL` / `API_URL`)
   - Credentials: `AUTH_MODE`, `PLAN_KEY_ENV`, `API_KEY_ENV`, `AUTH_REFERENCE`, `AUTH_KEYCHAIN_FALLBACK`
   - Key Fallback: `if [ -z "${PLAN_KEY:-}" ] && [ -n "${API_KEY:-}" ]; then export PLAN_KEY="$API_KEY"; fi`
   - Models: `MODEL`, `MODEL_OPUS`, `MODEL_SONNET`, `MODEL_HAIKU`, `MODEL_SUBAGENT`, `MODEL_ALIASES`
   - Tokens & Reasoning: `CONTEXT_TOKENS`, `AUTO_COMPACT_TOKENS`, `EFFORT`
   - Assets: `ASSET_PROFILE="<name>"` (or `"empty"` for pure gateways)
   - Hooks: `PRE_START`, `POST_STOP`, `HEALTH_CHECK_URL`, `EXTRA_ENV`

3. **Check POSIX Shell Syntax**:
   ```sh
   sh -n providers/<provider>.sh
   dash -n providers/<provider>.sh
   ```

> See [Archetypes & Templates Reference](references/archetypes-and-templates.md) for complete copy-paste templates for all 5 archetypes.

---

### Phase 3: 配置自动化切换 MCP (Session-Scoped MCP in `lib/provider-assets.js`)

Configure automated, zero-collision tool injection for the provider's companion tools:

1. **Pure Model Gateways**:
   - If the vendor has no official MCP tools, declare `ASSET_PROFILE="empty"` in `providers/<provider>.sh`.
   - No edit needed in `lib/provider-assets.js`. Claude Code runs without extraneous tools.

2. **Vendors with Companion MCPs**:
   - In `lib/provider-assets.js`, add `else if (profile === '<provider>')`.
   - **Namespace Rule**: Prefix all tool names with `crouter-<provider>-<tool>`.
   - **Credential Gate Rule**: Wrap credentialed tools inside `if (planToken)` or `if (activeToken)`.
   - **Transport Recipe Selection**:
     - *Python UVX*: Pinned version package via `command: 'uvx'`.
     - *Node NPX*: Pinned npm package via `command: 'npx'`.
     - *Streamable HTTP*: `{ type: 'http', url: '...', headers: { Authorization: 'Bearer ' + token } }`.
     - *SSE*: `{ type: 'sse', url: endpoint }` (validate hostname against whitelist).
     - *Public Docs*: Zero-auth HTTP tools mounted unconditionally.

3. **Session Environment & Plugins (`lib/assets.sh`)**:
   - If tools require runtime environment variables, add to `PROVIDER_ASSET_ENV` in `lib/assets.sh`.
   - If vendor has custom session skills, declare `ASSET_PLAN_PLUGIN_DIRS` or `ASSET_PLUGIN_DIRS`.

> See [MCP Automation Recipes](references/mcp-automation.md) for transport code snippets, credential gating, and session isolation lifecycle.

---

### Phase 4: 统一网关集成 (Unified Gateway Routing - `crouter all`)

Ensure the provider integrates smoothly with `crouter all` (`bin/gateway` and `lib/route-build.js`):

1. **Routing Mechanics**:
   - `crouter all` routes requests by model prefix: `<provider>/<model>`.
   - Candidates are built from `PLAN_URL` / `API_URL` or `BASE_URL`.
   - Cooldown and failover semantics trigger on 401/402/403/429.
2. **Verify Route Parsing**:
   ```sh
   ./bin/crouter all --check
   ```
   Confirm the provider appears with redacted credentials and correct model namespaces without issuing network requests.

---

### Phase 5: 严密验证与闭环交付 (5-Layer Automated Verification)

Choose the focused checks relevant to changed provider/auth/assets/routing behavior. Preserve the full `CLAUDE.md` release gate for a release or broad cross-provider change. The commands below are available checks, not an unconditional script for every edit.

```sh
# 1. Shell syntax check under POSIX sh and dash
sh -n providers/<provider>.sh
dash -n providers/<provider>.sh

# 2. Provider contract matrix assertions
# Add load <provider> and assert_eq statements in test/provider-matrix.sh
sh test/provider-matrix.sh
dash test/provider-matrix.sh

# 3. Provider asset rendering and isolation assertions (if ASSET_PROFILE != empty)
# Add assertions in test/provider-assets.sh
sh test/provider-assets.sh
dash test/provider-assets.sh

# 4. Regenerate/install compatibility launchers only when the changed contract
# requires it and the current task authorizes that installation. Inspect the
# installer target and preserve unrelated installed commands before running it.
# ./install.sh

# 5. Full regression for releases or broad cross-provider behavior changes
for test_file in test/*.sh; do sh "$test_file" || exit 1; done
for test_file in test/*.sh; do dash "$test_file" || exit 1; done

# 6. Git hygiene check
git diff --check
```
