# 来源适配器与 Claude Code 集成

## 两种接入，统一用户体验

**已有服务：** 用户提供 endpoint、协议和必要凭证；只读探测服务与目录，支持手填模型和未知元数据。不能因为 `/v1/models` 缺失就断言不能推理。保存不触发付费生成。标记“目录可读”与“已验证工具调用”为不同证据。

**托管反代：** 用户明确选择后，crouter 才可定位或安装依赖、配置、启动、登录、刷新和升级。依赖/版本来源可追溯，升级能回滚；不得远程下载脚本后未经审阅直接执行。开发此能力与在用户机器上实际安装、登录是不同授权。

Antigravity 是现有优先复用路径；未指定其他 App 时先完成通用适配器，不凭名称承诺支持其订阅模型。不要把 App 作为客户端启动入口。

## 适配器能力契约

在可用功能内实现 detect、validateConfig、listModels、health、start/stop、login/refresh、listAccounts、quota；不支持的操作显式返回 unsupported，不造空的成功结果。

每个适配器声明协议、目录认证、推理认证、支持的模态和工具/streaming、model mapping、错误分类、quota 能力、进程所有权和版本范围。适配器把上游事实转成共同结构，不自己绕过核心计费/来源策略。

凭证只能发送到用户选定且绑定的 origin；跨域重定向不携带认证，scheme/URL/query 正确处理，拒绝目录元数据提供的任意执行指令。localhost 反代是合法来源，不能一刀切禁止内网；但要验证 URL 并默认监听 loopback。公共目录不应顺手接收推理 token。

先复用已经验证的 Messages 兼容服务；增加 OpenAI 等协议桥接时，只为明确来源实现所需子集并做工具、图片、思考字段、SSE 和错误测试，不能当作通用全协议网关重写。

如果上游已管理账号池，选择一个调度权威：上游持有账户轮换时 crouter 只调度该来源并消费其支持的状态；只有上游明确暴露账户选择契约才细分。不得同时盲目轮换或虚构上游剩余额度。

## Claude Code 原生模型菜单

2026-11-07 重新核查官方 modelPicker、gateway 和 skills 资料，见 [基线与来源](baseline-and-sources.md)。文档支持与真实客户端验证是不同证据。

优先用临时会话 `--settings` 注入 `modelPicker`，从同一份 ModelVariant/route registry 生成菜单与路由。官方要求 v2.1.242+，读取 managed、--settings 和 user，但忽略 project/local settings。最高优先级的配置提供整份菜单，客户端不合并多份 lineup；不能只写 `.claude/settings.json` 就认定生效，也不能假设临时配置会自动保留用户菜单。

生成临时配置前明确采用的合并/保留策略，处理用户显式 --settings、managed allowlist、重复模型和自定义标签，不覆盖用户文件或绕过管理策略。测试实际可见项、禁用项与真实请求 ID。没有目标 CLI 时标明未验证，不用 stub JSON 检查替代菜单验收。

原生菜单展示标签不改变真实请求模型；保留明确来源和上游 ID。不要给 Qwen/Gemini 伪造 Claude 身份或未经验证的 `behavesAs` 能力。自定义模型和真实 Claude 别名需要分别验证。

网关 `/v1/models` 自动发现与显式 modelPicker 是不同路径。当前官方文档的自动发现过滤要求 ID 包含 claude 或 anthropic；不含这些字段的模型不能仅靠该端点保证进入菜单。不要为绕过过滤而伪造模型身份，改用经过实测的显式菜单。运行时目录热刷新也需单独验证，无支持则对新会话生效并说明。

兼容性表记录版本、注入方式、实际菜单、请求 model、主/辅助路由、context、effort、MCP 与会话恢复结果；不硬编码未来最新版本，也不把当前语法要求误写成所有能力的最低版本。

## 切换分级

1. 同模型换候选：网关在响应提交前处理，遵循来源/费用范围。
2. 兼容模型切换：经验证的原生菜单更新后续请求，在途请求不改写。
3. 不兼容变化：历史超窗口、图片/工具/思考块不支持、本地后端或 session assets 改变。明确新开/恢复或压缩选择，不丢历史、不用普通消息替换系统约束、不宣称无损。

写状态文件不会更新已启动进程的环境变量；某些 effort/压缩能力可在会话内改变，仍需按版本和实际请求核验，不能笼统说全部固定或全部可热换。主模型切换不覆盖显式辅助分工。

MCP/插件保持严格会话隔离。旧客户端降级应说明原因，但不能把日常操作重新变成冗长参数。可选 claude 包装入口的二进制发现、防递归和 stdin 契约见验收矩阵；它不是安装器默认创建的入口。

## 最低真实验收

经授权的非生产样例：进入 Claude Code，在原生菜单找两个不同家族模型，分别完成文本与无害工具回合，核对实际路由；再测长历史、取消、恢复和并发隔离。收费、登录和账号权限不在 CI 默认开启。没有凭证或 CLI 就记录未执行，不伪造全功能兼容。
