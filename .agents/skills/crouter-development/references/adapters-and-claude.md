# 来源适配器与 Claude Code 集成

## 两种接入，统一用户体验

**已有服务：** 用户提供 endpoint、协议和必要凭证；只读探测服务与目录，支持手填模型和未知元数据。不能因为 `/v1/models` 缺失就断言不能推理。保存不触发付费生成。标记“目录可读”与“已验证工具调用”为不同证据。

**托管反代：** 用户明确选择后，crouter 才可定位或安装依赖、配置、启动、登录、刷新和升级。依赖/版本来源可追溯，升级能回滚；不得远程下载脚本后未经审阅直接执行。开发此能力与在用户机器上实际安装、登录是不同授权。

Antigravity 是现有优先复用路径；未指定其他 App 时先完成通用适配器，不凭名称承诺支持其订阅模型。不要把 App 作为客户端启动入口。

## 适配器能力契约

在可用功能内实现 detect、validateConfig、listModels、health、start/stop、login/refresh、listAccounts、quota；不支持的操作显式返回 unsupported，不造空的成功结果。

每个适配器声明协议、目录认证、推理认证、支持的模态和工具/streaming、model mapping、错误分类、quota 能力、进程所有权和版本范围。适配器把上游事实转成共同结构，不自己绕过核心计费/来源策略。

凭证只能发送到用户选定且绑定的 origin；跨域重定向不携带认证，scheme/URL/query 正确处理，拒绝目录元数据提供的任意执行指令。localhost 反代是合法来源，不能一刀切禁止内网；但要验证 URL 并默认监听 loopback。公共目录不应顺手接收推理 token。

先复用已经验证的 Messages 兼容服务；增加 OpenAI 等协议桥接时，只为明确来源实现所需子集并做工具、图片、思考字段、SSE 和错误测试，不能当作通用全协议网关重写。

如果上游已管理账号池，选择一个调度权威：上游持有账户轮换时 crouter 只调度该来源并消费其支持的状态；只有上游明确暴露账户选择契约才细分。不得同时盲目轮换或虚构上游剩余额度。

## Claude Code 原生模型菜单

2026-10-30 核查的官方资料见 `baseline-and-sources.md`。具体支持范围仍须与测试的 Claude Code 版本一起记录。

优先用临时会话 `--settings` 注入 `modelPicker`，从同一份 ModelVariant/route registry 生成菜单与路由。官方文档称 `modelPicker` 自 v2.1.242 可用，接受 `--settings`，但忽略 project/local settings；不能仅写 `.claude/settings.json` 就认定有效。复用用户显式 settings 时应语义合并、尊重管理策略并测试优先级，不覆盖用户文件。

原生菜单展示标签不改变真实请求模型；保留明确来源和上游 ID。不要给 Qwen/Gemini 伪造 Claude 身份或未经验证的 `behavesAs` 能力。自定义模型和真实 Claude 别名需要分别验证。

网关 `/v1/models` 自动发现与显式 modelPicker 是不同路径；自动发现有开启条件、过滤及缓存行为，不能只实现端点就承诺所有模型进入菜单。运行时新增来源/模型是否能热刷新要单独验证；没有支持则对新会话生效并明确说明。

构建兼容性表：测试版本、注入方式、可见菜单项、实际请求的 model、主/辅助模型路由、context、effort、MCP 和会话恢复结果。只生成 JSON 的单测不足以证明真实菜单可用。

## 切换分级

1. 同模型换候选：由网关在响应开始前完成，遵循既定来源/费用范围。
2. 兼容模型切换：经验证的原生菜单更新后续请求；在途请求不改写。
3. 不兼容变化：包括历史超出窗口、图片/工具/思考块不被新模型接受、本地后端与 session assets 改变。先检查，必要时明确新开或恢复会话；不得丢弃历史、用用户消息偷偷替代系统约束或宣称无损。

环境变量在进程启动后不会因为写状态文件而更新。某些 effort/压缩设置有会话内能力，也必须按具体版本与请求验证，不能沿用“全部固定”或“全部能热换”任一笼统假设。辅助模型显式分工不应被主模型切换覆盖。

MCP/插件切换保留严格会话隔离，不把一个订阅的工具与凭证带到另一个来源。旧客户端不支持目标能力时提供明确降级说明；降级不能退回要求所有日常操作手写复杂参数。

## 最低真实验收

经用户授权的非生产样例：从 crouter 进入 Claude Code，在原生菜单找到两个不同家族的已配置模型，分别完成文本与一个无害工具回合，核对实际路由；在长历史、取消、重新进入会话、两个同时运行的会话中检查隔离。收费、登录与账号权限不可在 CI 中默认启用。没有凭证或 CLI 时记录未执行，不伪造“全功能兼容”。
