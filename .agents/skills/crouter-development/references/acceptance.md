## 测试层级

纯逻辑：计划解析、模型身份、策略、错误分类、状态迁移，使用固定时钟和随机种子。

Mock HTTP：记录实际 endpoint/header/model，注入错误、断流、慢响应、跨域重定向与取消；假凭证固定为明显的测试值，绑定 loopback，不联系供应商。

伪终端：测试完整按键、Unicode 分片、粘贴、resize、取消与终端恢复。不能用只检查静态输出的测试替代交互行为。

离线整合：临时 HOME/XDG/STATE、stub claude/security/服务，屏蔽真实 Keychain 和用户 config.sh。以仓库当前 CI 和 CLAUDE.md 为准，不执行不认识的 provider hooks。

真实兼容：明确授权后在实际 Claude 版本、终端和目标平台验证。真实推理可能计费，与离线测试分开。真实额度耗尽不应作为必须付费触发的测试，用 mock 覆盖。

小型技能/文档改动运行本包校验、链接、JSON 和语法检查即可；运行时代码变更按风险跑受影响测试，发布前全部 shell suites 在 sh 和 dash 下运行。检查所有 Node 入口，尤其不能漏掉 bin/crouter-models 和 bin/openrouter-models。缺少 shellcheck/平台工具时记录缺失，不能写成通过。

## 技能行为评测

`evals/cases.json` 提供正向、反向和边界提示词。评测 agent 应在隔离 checkout、假凭证与 mock 服务中运行；对照 must/must_not 逐项核对计划、工具调用和最终证据。结构脚本只校验这些案例格式，不会自动运行 LLM 评测。

关键失败一票否决：把 App 当产品客户端、擅自扩大付费/数据流向、只包装 flags 不改操作、流式重放、覆盖用户工作、未执行却宣称测试通过。没有凭证时完成离线部分并报告限制是正确行为，不是失败。

## 完成定义

功能可从真实入口触达，成功与失败/取消路径都有测试；相同应用操作被 TUI/CLI 复用；状态和 migration 不泄漏凭证；适用验收逐项有证据；README/帮助与实际能力一致；明确列出未验证的客户端版本、平台和上游。通过 package 静态校验绝不替代这些条件。
