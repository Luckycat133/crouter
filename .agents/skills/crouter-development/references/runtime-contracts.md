# 运行时与自动调度契约

这是目标契约；具体模块名称可随代码调整，语义不能降低。先保持现有 shell 外壳与 Node 运行时，不为重构而重写所有 provider。

## 分层与启动顺序

界面/CLI → 共用应用操作 → 配置解析与策略 → 会话运行时 → 来源适配器。shell 与 Node 之间用结构化数据和显式退出码，不 eval 用户输入、不解析菜单文本；原有可信 provider 脚本仍须按项目信任边界处理。

顺序：读取非秘密元数据→选择来源/模型→纯解析生成 LaunchPlan→用户确认→按计划解析必要凭证→启动所需服务→生成临时会话配置→启动 Claude Code→清理自己拥有的资源。

目录请求单独执行，按需读取其专用凭证；不能为了看目录先启动完整推理会话。`--apply-only`/保存配置停在计划持久化，不执行 PRE_START、推理、MCP 初始化或服务启动。老 provider 的选模型逻辑先提取为无副作用解析步骤，再保留启动 hooks；不能简单把所有 PRE_START 后移而丢掉其中的模型归一化。

LaunchPlan 至少携带 schemaVersion、model identity、source/account scope、candidate refs、tier mapping、context/output/compact/effort、capability constraints、required services/assets、client compatibility、warnings；不含明文秘密。预览与实际启动使用同一个计划，防止二次解析漂移。

## 数据关系

| 对象 | 必须表达的关系 |
| --- | --- |
| Source | provider/adapter、协议、endpoint、目录策略、启用状态、是否由 crouter 管理 |
| Account | 所属来源、用户标签、认证方式、登录状态；不直接等同于 key |
| QuotaPool | 共享额度身份、来源/账户范围、观测来源/时间、未知或下一恢复时间 |
| CredentialRef | 凭证存储引用、所属账户、绑定的计费面、有效状态；不含实际 token |
| ModelVariant | 真实版本、上游 ID、模态/工具能力、窗口与证据；不能仅凭显示名合并 |
| Candidate | 来源/账户/额度池/凭证引用 + endpoint/header/model map/计费类型/优先级 |
| Session | 会话 ID、不可变计划版本、当前模型、允许来源集合、已授予费用策略 |

模型状态绑定来源和 ModelVariant，而非单个 provider-context 文件。未知 context 必须清除旧模型残值；窗口、最大输出和压缩阈值分别校验。优先级建议：显式用户覆盖→经过审计的模型特定适配限制→新鲜可信目录→provider 回退值→未知；不让目录无条件覆盖实际后端硬限制。显示有效值及来源。

持久化使用版本化 schema、同目录临时文件+原子替换、适当锁和 0600/0700 权限；校验类型、路径、model ID、数字上界，拒绝损坏状态和路径逃逸。model ID 不拼进 shell、JS 源码或路径。旧状态迁移可重复、备份可回滚，失败不修改真实凭证。

## 候选筛选与调度

先按用户允许来源、锁定范围、真实模型等价、请求能力、计费策略、账户状态筛选，再排序。不可用候选不应因“全都失败”就绕过硬约束重新加入。

同一请求捕获候选和策略快照；显式变更只影响后续请求。主模型、辅助模型、子代理都有独立声明映射，不因为全局变量被改动而漂移。

默认粘性选择：健康候选继续用；失败后在允许集合内切换。已知共享额度耗尽标记整个 QuotaPool；未知共享关系不假设每把 key 独立。两个会话共享的健康状态需要锁/版本或受控协调；不为此先引入全局守护进程。单进程实现必须诚实说明跨进程限制。

## 失败分类

| 观测 | 处理原则 |
| --- | --- |
| 401 / 凭证明确失效 | 适配器支持时最多一次受控刷新，刷新单飞；失败标记需重新登录，不无限重试 |
| 403 | 区分模型权限、策略拒绝和账号问题；模型级拒绝不得禁用整个账户；未知按保守错误处理 |
| 402 / 额度或余额耗尽 | 依据供应商错误契约定位额度池，恢复时间未知则不伪造；不能自动开按量兜底 |
| 429 | 结合 Retry-After、错误体和来源契约区分短时限流与周期额度；按作用域冷却 |
| 可恢复 5xx / 连接失败 | 有限退避和总 deadline；每候选重试耗尽后评估下一候选，不无限轮转 |
| 400 / 请求能力不支持 | 不通过不断换 key 掩盖错误；仅应用已验证、模型作用域内的兼容转换 |
| 所有候选冷却中 | 返回明确可重试信息，或在总预算内等待最早恢复；不无条件再打冷却候选 |

状态至少区分 ready、cooldown、quota-exhausted、reauth-required、disabled、unknown；权限错误可作用于账户×模型。成功不能清除无关模型的限制。调度支持 fake clock 测试，不依赖长 sleep。

## 重试与流式边界

限制每候选次数、总尝试次数和墙钟等待；上游反代已重试时避免乘法放大。客户端断开、取消或 deadline 到期，销毁上游请求、待执行 timer 和读取流。

尚未收到响应也不证明上游没执行或没计费。网络错误按请求发送阶段分类；只有策略允许且未对客户端提交响应时才重试，记录不确定结果，不承诺 exactly-once。有官方幂等机制时按其契约使用，不随意发明 header。

一旦向客户端发送响应头/流事件，不再切换候选重放本请求。中途断流明确终止；不拼接回答、不重复工具调用。保留正常 SSE、tool_use/tool_result 关联、usage、停止原因和已验证的必要 headers。心跳不能伪造模型事件。请求体、响应目录、超时和并发要有边界。

最后错误应保留有用且脱敏的上游类型、状态与 Retry-After；不要把认证、权限、上下文过长全部改成含糊的 502。日志只有 request/session/candidate 标识和状态，不含 prompt、响应正文或 secrets，调试正文需另行显式授权。

## 凭证、费用与生命周期

凭证存储适配器复用现有 Keychain/环境引用/受控 portable 方案；不要趁 UI 改造把钥匙明文搬到 JSON。无回显输入失败要恢复终端，批量写入要有失败补偿。可控缓冲区及时释放，但不宣称 JavaScript 字符串可保证内存清零。

不自动把 API key 当套餐 key。新费用授权必须明确，迁移来的含糊旧策略不能被升级成更宽授权。保存元数据或上传 skill 不是授权发起付费验证。按量额度估算未知时不得以 0 放行。

保留原生 Claude 登录，不提取其 OAuth/订阅凭证到普通网关。其他明确授权的 App 反代使用自己的登录边界。只停止自己启动且仍验证归属的进程；不能仅看端口就 kill。多个会话共享服务需要显式引用/所有权，退出一个会话不终止其他会话；配置冲突应隔离实例或报明原因，不能重启别人的服务。
